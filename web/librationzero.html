How a key becomes keyless

  1. Deploy with a bootstrap key. Each contract is published by a deploy wallet that can only set its launch parameters and wire the registry seams. That key never takes custody — every contract is non-custodial, so funds move only on a transfer you sign in your own wallet.
  2. Lock the parameters. Once the launch values are set and verified on-chain, there is nothing left for an owner to do.
  3. Renounce. The owner calls renounce, which erases the owner slot in the contract's own storage. The transaction is public; the slot reads empty from that block forward, and no address — not the deployer, not any developer, not Free the Bird — can call a privileged method again. The code is frozen as deployed.
  4. Born keyless. The lending contract (FtbLoanBook) ships with no owner method at all: there is nothing to renounce, and it is immutable from its first block.

The table above reads each contract's owner slot live from the chain. Keyless means that slot is empty — confirm it yourself on the explorer. Deployment and development hold no key to the live protocol.
